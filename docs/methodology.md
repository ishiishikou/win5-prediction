# Methodology

## 1. 目的

AIによるWIN5予想が、長期的にどの程度の的中率・回収率を持つかをフォワードテストする。

単発の大当たりではなく、**締切前に固定された予想を積み上げて評価する**。

## 2. 予算

標準は1開催3,000円、1点100円、最大30点。

追加の実験買いを行う場合は、標準30点とは別に `exploratory` として記録する。

## 3. 予想の作り方

各レースで馬ごとの勝率を推定し、選択した馬の勝率合計をそのレースの通過確率の近似とする。

5レースの通過確率を `P1 ... P5` としたとき、単純化した全体的中確率は

`P(WIN5) ≈ P1 × P2 × P3 × P4 × P5`

として扱う。

30点制約の中で、各レースに1頭追加した場合にこの積がどの程度改善するかを比較する。

### 市場評価

単勝オッズは市場の情報集約として利用するが、そのまま真の勝率とはみなさない。必要に応じて逆数を正規化して市場由来の相対確率を作り、モデル評価と比較する。

### 高配当への対応

WIN5の期待払戻を厳密に推定するには、馬単体の単勝オッズだけでなく、WIN5購入者の組合せ分布が必要になる。公開情報だけでは十分に観測できないため、当面は

- 的中確率最大化を主目的
- 人気薄に明確な根拠がある場合だけ価値側へ寄せる

という二段構えにする。

## 4. 事前登録

予想ファイルは最初の対象レースの締切前にコミットする。

締切後は予想ファイルを更新しない。結果や反省は別ファイルに記録する。

これにより、結果を見てから買い目を作り直す後知恵を排除する。

## 5. 評価指標

- `stake_yen`: 実際に計上する投資額
- `payout_yen`: 払戻額
- `net_yen = payout_yen - stake_yen`
- `return_rate = payout_yen / stake_yen`
- `net_roi = net_yen / stake_yen`
- `race_coverage`: 5レース中、予想集合に実際の勝ち馬が含まれた数
- `win5_hit`: WIN5的中の真偽
- `audited`: GitHub上で締切前に予想が固定されたか

集計では、
1. 全実購入
2. `audited=true` のフォワードテスト
を分けて表示する。

## 6. ベンチマーク

JRA公式によるWIN5の現在の設定払戻率は70%。

- https://www.jra.go.jp/kouza/win5/carry/
- https://www.jra.go.jp/faq/pop04/3_14.html

短期の収支は分散が極めて大きいため、数開催の結果だけで優位性を判断しない。

## 7. 情報源の優先順位

1. JRA公式
2. 競馬場・主催者等の一次情報
3. 信頼できるデータサイト
4. 予想サイト・SNS・コミュニティ

3と4は補助情報であり、一次情報と矛盾した場合は一次情報を優先する。
